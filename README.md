# 文獻書房

論文整理工具。把論文 PDF 丟進去，自動整理成一個可以搜尋、比較、回查原文的資料庫。

目前是**示範階段**：介面和邏輯已經確定，自動擷取還沒做。

---

## 要解決什麼

讀了一堆論文，最後：

- 忘記自己讀了什麼
- 想不起某個資訊出自哪一篇
- 要寫論文或討論時，引用又要翻半天
- 最糟的是——分不清某個論點是看來的，還是自己腦中推論出來的

## 三條鐵則

這三條決定了整個工具的設計，不能妥協：

1. **只處理你上傳的 PDF。** 不讓 AI 自己上網找來路不明的資訊。
2. **沒有的不要掰。** 原文沒寫就留空、標「正文未提供」，不猜、不填、不推測。
3. **可以連 PubMed，但要交代清楚。** 顯示連結、標題、作者、為什麼找到這篇、PubMed 上原本有什麼。

## 示範站（index.html）

單一 HTML 檔，不需要安裝任何東西，用瀏覽器直接打開就能看。資料全部寫在檔案裡，不會連到任何伺服器。

### 裡面有什麼

| 功能 | 說明 |
|---|---|
| 書架 | 每篇論文是一本書，可依主題／期刊／年份／物種重新排列 |
| 書頁 | 書目、作者角色、摘要、關鍵字、實驗清單、討論、參考文獻 |
| 實驗卡 | 每個實驗的動物、樣本數、條件表、結果、對應的圖 |
| 搜尋 | 可依實驗、條件、作者、期刊、關鍵字、圖來找 |
| 比較表 | 搜尋同一個實驗時，並排列出各篇的條件、結果、圖 |
| 圖目錄 | 68 個圖面板，可依類型篩選（螢光圖、電生理、長條圖、WB band⋯） |
| 參考文獻分析 | 哪幾條被引用最多次、在哪裡被引用、兩篇的共同引用比對 |
| PubMed | 查書庫裡沒有的論文，附 PMID 連結與「為什麼找到它」 |
| 筆記 | 分「論文說的」（必填頁碼）和「我的推論」（紫色標示） |

### 每個欄位都掛頁碼

畫面上每個擷取出來的欄位後面都有 `p.N`，點下去會說明這筆資料出現在原文第幾頁。

**這是整個工具最重要的設計。** 自動擷取一定會出錯，但只要每一格都能一鍵跳回原文，錯誤三秒就抓得到。比「保證不會錯」實在得多。

## 示範資料是真的

書架上的兩本書不是編的，是從兩篇真實論文的 PDF 讀出來的：

| | 論文 | PMID |
|---|---|---|
| A | REM sleep-active MCH neurons are involved in forgetting hippocampus-dependent memories（Science 2019）| 31604241 |
| B | Sleep loss diminishes hippocampal reactivation and replay（Nature 2024）| 38867049 |

論文 PDF **沒有**放進這個 repository（版權）。

擷取出來的內容：20 個實驗、68 個圖面板、兩篇共 108 條參考文獻、四層關鍵字。
PubMed 的資料是真的用 NCBI E-utilities API 查回來的，不是手打的。

## 已知的限制

這些都實測過，不是猜的：

- **上標式引用抓不準。** `memory⁵,⁶` 這種格式抽成純文字後會和統計數字混在一起——`0.57 Hz` 會被讀成「引用第 57 條」。目前規則收得很緊（只認小寫字母後緊接數字），寧可漏抓也不要錯抓。**正確解法是讀 PDF 的字型大小與基線**（PyMuPDF `page.get_text("dict")`），還沒實作。
- **跨頁的參考文獻會整段掉。** 論文 A 的 31 條掉了第 5、8、29；論文 B 的 77 條掉了第 4、26、40、49、71、74。原因都是作者名被切在欄位邊緣。處理方式：讀到多少留多少，不補。
- **圖片本身還沒抽出來。** 目前只有圖號、類型、頁碼、對應實驗。要真的裁圖需要 PyMuPDF 或 poppler。
- **圖的類型是從圖說文字判讀的**，可能判錯。但圖號和頁碼是原文印的，不會錯。
- **自動擷取還沒做。** 示範站的資料是人工讀完整理的。

## 擷取時要注意的坑

- **關鍵實驗條件常常只在圖說裡。** 例：NOR 的保留期 1.5 小時、電擊強度強／弱，正文都沒寫，只有 Fig. 1 圖說有。要同時涵蓋正文、Methods、圖說、補充資料。
- **樣本數和鼠齡常常不在 PDF 裡。** 論文 A 的 n 全在 Table S1–S4 補充資料；兩篇都沒給鼠齡。
- **PMID 是整個系統的骨架。** 比對是否同一篇、查 MeSH、連 PubMed、抓預印本版本都靠它。NIH author manuscript 版的參考文獻會附 PMID（A 篇 24/31、B 篇 63/77），但從期刊官網下載的 PDF 通常沒有。
- **同一份研究 PubMed 可能有兩筆**（正式版＋預印本），數字常常不一樣。要掛在同一本書下，不可混用。

## extract_refs.py

從論文 PDF 拆出參考文獻清單，統計每一條在內文被引用幾次、出現在哪幾頁。

需要 `pdftotext`（poppler-utils 或 xpdf）。

```bash
python extract_refs.py paper.pdf
python extract_refs.py paper.pdf --json out.json
```

會自動判斷引用格式是括號式 `(17)` 還是上標式，並在輸出中標明這次的統計可不可靠。

已處理的狀況：含中文的檔案路徑（Windows 上的 xpdf 打不開，所以先複製到純 ASCII 暫存路徑）、壓縮流有損但文字仍抽得出來的 PDF、沒有參考文獻區塊的文件（直接說找不到，不猜）。

### 架構方向

**正式版應該做成在本機跑的程式，不是網站。** 理由：

- **版權**——論文圖存在自己電腦裡是合理使用，傳到雲端主機是另一回事
- **檔案大小**——一篇 PDF 就可能 5 MB，一百篇幾百 MB
- **速度**——PDF 解析和裁圖在本機快得多

只有查 PubMed 的時候才連網。
